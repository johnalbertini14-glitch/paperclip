# REVA-490 — Email Webhook Signature Verification

## Issue
SendGrid/Mailgun/generic email webhooks lack signature verification, allowing attackers to send fake webhook events.

## Current State
- `POST /webhook/sendgrid` accepts events without any signature validation
- No verification headers checked (X-Twilio-Email-Event-Signature, X-Mailgun-Signature)
- Vulnerable to fake event injection

## Implementation Plan

### Phase 1: Core Signature Verification Utilities
1. Create signature verification helpers:
   - `verify_sendgrid_signature(body, signature_header, api_key)` — HMAC-SHA256
   - `verify_mailgun_signature(body, signature_header, signing_key)` — HMAC-SHA256
   - `verify_generic_webhook_signature(body, signature_header, secret)` — HMAC-SHA256

### Phase 2: Data Model Updates
1. Add webhook signing secret fields to user_integrations:
   - `sendgrid_webhook_signing_secret` — For webhook signing verification
   - `mailgun_webhook_signing_secret` — For webhook signing verification

### Phase 3: SendGrid Webhook Verification
1. Extract signature from `X-Twilio-Email-Event-Signature` header
2. Get signing secret from database
3. Verify signature before processing
4. Return 401 Unauthorized if verification fails
5. Log failed verification attempts

### Phase 4: Mailgun Webhook Support (Optional)
1. Add `POST /webhook/mailgun` endpoint
2. Implement same verification pattern

### Phase 5: Generic Webhook Support (Optional)
1. Add configurable webhook support
2. Allow users to specify signing secrets

### Phase 6: Testing
1. Unit tests for signature verification functions
2. Integration tests for webhook endpoints
3. Tests for missing/invalid signatures
4. Tests for valid signatures

## Files to Modify
- `backend/routes/real_integrations.py` — Add signature verification to sendgrid_webhook
- `backend/tests/test_integration_health_and_webhook.py` — Add signature verification tests
- Potentially: database schema migration for new fields

## Security Considerations
- Use constant-time comparison for HMAC verification (hmac.compare_digest)
- Don't log raw signatures or secrets
- Return generic 401 responses (don't reveal why verification failed)
- Reject requests missing required signature headers
